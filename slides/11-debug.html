print() vs デバッガ

print() デバッグ

  • print文を書く → 実行 → 確認 → 削除
  • 毎回コードを変更する必要
  • 深いネストの変数が見づらい
  • 実行の流れが見えない
  • 消し忘れて本番に残る...

デバッガ

  • コード変更不要
  • 任意の場所で一時停止
  • 全変数の値を一覧表示
  • 1行ずつ実行を追跡
  • 条件付きで止められる

ブレークポイント

設定方法

行番号の左側をクリック → 赤い丸が表示される = ブレークポイント
プログラムがこの行に到達すると一時停止する。

種類

種類設定方法説明
通常行番号クリックその行で必ず停止
条件付き右クリック → 条件条件が true の時だけ停止
Log Point右クリック → Log停止せずにログ出力
ヒットカウント右クリック → HitN回目の到達で停止

デバッグ操作

操作アイコンショートカット説明
続行▶F5次のブレークポイントまで実行
ステップオーバー⤵F10次の行へ（関数の中に入らない）
ステップイン↓F11関数の中に入る
ステップアウト↑Shift+F11現在の関数から出る
再起動↻Cmd+Shift+F5最初からやり直し
停止■Shift+F5デバッグ終了

デバッグパネル

Variables

現在のスコープの全変数と値を表示。
値を直接編集することも可能。

Watch

監視したい式を登録。
例: len(data), x > 10

Call Stack

関数の呼び出し階層を表示。
どこから呼ばれたか追跡。

Debug Console

停止中に任意のコードを実行。
変数の値を確認・変更。

条件付きブレークポイント

使い方

行番号を右クリック → "Add Conditional Breakpoint" → 条件式を入力

# 例: i が 100 の時だけ停止
条件: i == 100
# 例: data がNoneの時だけ停止
条件: data is None

Log Point（停止しないブレークポイント）

print文の代わりに使える。コードを変更せずにログ出力。
書式: Processing item {item.name}, count={len(items)}

デバッグ演習（20分）

  1. 以下のバグ入りコードを作成:
    def sum_list(lst):
      total = 0
      for i in range(len(lst) + 1):
        total += lst[i]
      return total
  2. ブレークポイントを設定して F5 でデバッグ開始
  3. F10 でステップ実行しながら変数 i を監視
  4. バグの原因を特定して修正
  5. 条件付きブレークポイント（i == len(lst)）を試す

まとめ

デバッガはprint文の上位互換

コード変更不要、全変数表示、ステップ実行。

F5, F10, F11 を覚える

開始(F5)、ステップオーバー(F10)、ステップイン(F11)。
