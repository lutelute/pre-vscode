閉じても大丈夫

ウィンドウを閉じてもファイルは消えない。VS Code はビューア。ファイルの実体はディスク上にある。次回同じフォルダを開けばタブ・カーソル位置も復元。

Remove Folder ≠ 削除

マルチルートワークスペースで「Remove Folder from Workspace」してもサイドバーから外れるだけ。ファイル自体は一切消えない。

履歴の管理

Cmd+Shift+P → Clear Recently Opened で最近開いたフォルダの履歴をクリアできる。

玄人あるある 5選

慣れた人ほど油断する危険パターン

ADV #1 マルチルートの Git 事故

Workspace (2 folders)
FRONTEND (Git: main)
src/App.tsx
package.json
BACKEND (Git: dev)
api/routes.py
requirements.txt
1# backend のファイルを編集中…
2# でも Source Control は
3# どっちのリポジトリ？
main ← どっちの main?

何が起きるか

Source Control に両方のリポジトリが表示。選択を間違えると backend の変更を frontend にコミット。

対策

1
Source Control のリポジトリ名を毎回確認
2
コミット前に git diff --staged
3
そもそも別ウィンドウで開く方が安全

ADV #2 Workspace 設定の意図しない汚染

// .vscode/settings.json に意図せず書き込まれた
{
"editor.fontSize": 18, // ← 個人の好み
"editor.tabSize": 4,
"python.defaultInterpreterPath":
"/Users/tanaka/.venv/bin/python" // ← 田中さんのパス！
}

git push → チーム全員の環境が壊れる

User 設定 vs Workspace 設定

設定内容どこに書く？
フォントサイズ・テーマUser（個人の好み）
Formatter・LinterWorkspace（チーム共通）
Python パスUser（環境依存）

防止策

設定GUIの上部タブで User / Workspace を常に確認。git diff で .vscode/ の意図しない変更を検出。

ADV #4 Remote SSH でローカルと混同

ローカル
mainUTF-8
サーバー
SSH: pws-160coreUTF-8

危険シナリオ

SSH接続中にファイルを削除 → サーバー上のファイルが消える。ローカルのゴミ箱には入らない。Git管理外なら復元不可。

確認ポイント

1
ステータスバー左下の SSH: hostname を常に確認
2
リモートでの削除は慎重に（ゴミ箱がない）
3
重要ファイルは必ず Git管理下 に
4
ネットワーク切断→ファイル破損もありうる → autoSave 推奨

ADV #5 .vscode/ のチーム管理指針

ファイルGit に含める？理由
extensions.json✓ 含める推奨拡張機能はチーム共通にすべき
settings.json△ 共通部分のみFormatter/Linter = 共通、Font/Theme = 個人
tasks.json✓ 含めるビルド・テスト手順は統一すべき
launch.json△ 要議論実行環境（Docker/ローカル）が人により異なる
*.code-workspace✗ 含めないローカルの絶対パスが含まれるため

ベストプラクティス

チームで最初に .vscode/ の管理方針を決める。.gitignore に入れるファイルを明文化。PR レビューで .vscode/ の差分に注意。
