フォルダを開く 3つの方法

A. Open Folder（基本）

Cmd+O or code .

1つのプロジェクト = 1つのウィンドウ。
これが基本。迷ったらこれ。

B. Add Folder to Workspace

File → Add Folder to Workspace

1つのウィンドウに複数フォルダ。
上級者向け。事故の元。

C. 新しいウィンドウで開く

code -n /path/to/project

完全に独立したウィンドウ。
複数プロジェクト並行開発に安全。

プロジェクトが終わったら

OK: そのまま閉じる

Cmd+W でウィンドウを閉じるだけ。VS Code は最後の状態を記憶している。次に同じフォルダを開けば、タブやカーソル位置も復元される。

OK: Remove Folder from Workspace

マルチルートワークスペースの場合、不要になったフォルダを右クリック → Remove Folder from Workspace。プロジェクト自体は消えない（サイドバーから外れるだけ）。

注意: 「最近使ったフォルダ」のクリア

Cmd+Shift+P → Clear Recently Opened で履歴をリセットできる。溜まりすぎたら掃除。

フォルダの切り替えフロー

今のプロジェクト
作業中
→
別プロジェクトに移動
どうする？

同じウィンドウで開き直す

Cmd+O → 別フォルダを選択
or code /path/to/other

前のプロジェクトは閉じられる。
シンプルだが頻繁な切り替えには不向き。

新しいウィンドウで開く

code -n /path/to/other
or Cmd+Shift+N → Open Folder

両方のプロジェクトを並行で見れる。
推奨。

ウィンドウ間の切り替え

Cmd+\` (macOS アプリ切替)
or Ctrl+W → ウィンドウ一覧

Cmd+Shift+P → Switch Window も便利。

BEGINNER PITFALLS

初心者あるある 6選

誰もが一度はやる失敗

初心者あるある #1

ファイルをダブルクリックで開く

Finderで main.py をダブルクリック → VS Code が起動するが…

  • サイドバーにファイルツリーが出ない
  • プロジェクト全体の検索ができない
  • Git連携が効かない
  • .vscode/settings.json が読まれない
  • 拡張機能がプロジェクトを認識しない

正解: フォルダごと開く

Terminal
$ cd ~/projects/my-app
$ code .
# フォルダ全体が開く

code . を習慣にするだけで全て解決。

初心者あるある #2

ホームディレクトリを Open Folder する

code ~ や code /home/username で開いてしまう

  • 数万ファイルをスキャンしてVS Code が激重に
  • Git が意図しないリポジトリを検出
  • 検索結果が関係ないファイルだらけ
  • Remote SSH で特に深刻（サーバーのリソースを浪費）

正解: プロジェクトフォルダを指定

~/
├── × ここを開く → 全部スキャン
├── projects/
│ ├── my-app/ ← ここを開く
│ ├── analysis/ ← ここを開く
│ └── experiment/
└── Documents/

初心者あるある #3

ウィンドウを開きすぎて迷子になる

いろいろ開いているうちに、どのウィンドウがどのプロジェクトか分からなくなる。ターミナルで git push したら違うリポジトリだった…

対策

  • ステータスバー左下を見る習慣 — ブランチ名 = 今いるリポジトリ
  • タイトルバーにフォルダ名が表示されている
  • Cmd+Shift+P → Switch Window でウィンドウ一覧を確認
  • 不要なウィンドウはこまめに Cmd+W で閉じる
  • テーマ色をプロジェクトごとに変える（Peacock 拡張機能）

初心者あるある #4

「このファイルどこに保存した？」

Cmd+N で新規ファイルを作って保存するとき、意図しない場所に保存してしまう。Explorer に出てこなくて混乱。

対策

  • 新規ファイルはExplorer上で右クリック → New Fileが確実
  • 保存時のダイアログでパスを必ず確認
  • ターミナルで pwd を叩けば今いるディレクトリが分かる
  • Cmd+P でファイル名検索 — 見つからなければ開いているフォルダ外にある

初心者あるある #5

「フォルダを閉じたらファイルが消える？」

VS Code のウィンドウを閉じたり、サイドバーからフォルダを Remove しても、ファイルは絶対に消えない。VS Code はビューアであって、ファイルの実体はディスク上にある。

安心ポイント

  • ウィンドウを閉じる → ファイルはそのまま。次回開けば元通り
  • Remove Folder from Workspace → サイドバーから消えるだけ
  • 未保存のファイルがあれば保存するか聞かれる
  • 怖かったら git status で状態を確認してから閉じる

初心者あるある #6

「新しいプロジェクトをどう始める？」

既存のウィンドウに Add Folder to Workspace で追加するべき？新しいウィンドウで開くべき？

新しいウィンドウで開く（推奨）

$ code -n ~/projects/new-app

設定・Git・ターミナルが完全に独立。事故が起きない。

Add Folder（上級者向け）

frontend + backend を1画面で見たい時だけ。
Git操作やターミナルのカレントディレクトリに注意が必要。

ADVANCED PITFALLS

玄人あるある 5選

慣れた人ほどやらかす危険パターン

玄人あるある #1

マルチルートワークスペースの Git 事故

frontend/ と backend/ を1つのウィンドウに追加。Source Control パネルに両方のリポジトリが表示される。うっかり backend の変更を frontend にコミット…

対策

  • Source Control のリポジトリ名を必ず確認
  • コミット前に git status をターミナルで実行
  • git diff --staged で何をコミットするか確認
  • 迷ったら別ウィンドウで開く方が安全

ターミナルの罠

ターミナルの pwd が指すディレクトリに注意。マルチルートでは、ターミナルを開いたタイミングでカレントディレクトリがどちらかが決まる。

玄人あるある #2

Workspace 設定が知らないうちに汚染

GUI で設定を変えたつもりが .vscode/settings.json に書き込まれ、git push でチームメンバーの環境を壊す。

対策

  • 設定画面のタブ User / Workspace を意識する
  • 個人の好みは必ず User Settings に
  • チーム共通設定（formatter, linter）だけ Workspace に
  • git diff で .vscode/settings.json の意図しない変更がないか確認
  • .gitignore に入れるべき設定と入れるべきでない設定を整理

玄人あるある #3

ターミナルが違うフォルダを指している

VS Code のターミナルは起動時のカレントディレクトリを維持する。フォルダを開き直しても、古いターミナルは前のディレクトリのまま。

危険な例

1. project-A/ で作業開始 → ターミナル開く
2. project-B/ に Open Folder で切り替え
3. ターミナルはまだ project-A/ にいる
4. pip install → 違う venv に入る
5. git push → 違うリポジトリに push

対策

  • フォルダ切替後はターミナルを新しく開く
  • コマンド実行前に pwd を叩く習慣
  • git remote -v でリポジトリを確認
  • 古いターミナルはゴミ箱アイコンで閉じる

玄人あるある #4

Remote SSH でローカルのつもりがサーバー側

SSH接続中にファイルを削除 → サーバー上のファイルが消える。
ローカルのゴミ箱に入るわけではないので復元不可（Gitがなければ）。

対策

  • ステータスバー左下の SSH: hostname を常に確認
  • リモートファイルの削除は慎重に（ゴミ箱がない）
  • 重要なファイルは必ず Git 管理 下に
  • 拡張機能はローカル/リモートで別管理 — 入れ忘れに注意
  • ネットワーク切断時にファイルが壊れることもある → autoSave 推奨

玄人あるある #5

チーム間で .vscode/ の設定が衝突

A さんの launch.json は Docker 環境前提、B さんの launch.json はローカル直接実行。互いにコミットしてマージのたびに壊れる。

.vscode/ の管理方針

ファイルGit に入れる？理由
extensions.json入れる推奨拡張はチーム共通
settings.jsonチーム共通部分だけ個人設定は User Settings へ
launch.json議論が必要環境依存が大きい
tasks.json入れるビルド手順は共通化すべき
*.code-workspace入れないローカルパスが含まれる

まとめ

絶対やめること

  • ファイル単体をダブルクリックで開く
  • ホームディレクトリを Open Folder
  • どのウィンドウか確認せず git push
  • ローカル/リモートを混同して削除

常に意識すること

  • code . でフォルダごと開く
  • ステータスバーでブランチ/接続先を確認
  • ターミナルの pwd を信頼する
  • .vscode/ のチーム管理方針を決める
