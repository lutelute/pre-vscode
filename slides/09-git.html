Cmd+Shift+G でSource Controlパネルを開く (Ctrl+Shift+G on Win/Linux)

ファイルステータスインジケータ

記号色意味説明
M黄色Modified既存ファイルが変更された
U緑UntrackedGitで追跡されていない新規ファイル
A緑Addedステージングに追加された新規ファイル
D赤Deleted削除されたファイル
R紫Renamed名前が変更されたファイル
CオレンジConflictマージコンフリクトが発生

これらの記号はExplorer（サイドバー）とSource Controlパネルの両方に表示される

ガターインジケータ

1 import os
2 import json ← 追加された行（緑）
3
4 name = "updated" ← 変更された行（青）
5 value = 42
6 result = name ← この上で行が削除された（赤三角）

緑 = 追加 / 青 = 変更 / 赤三角 = 削除。ガターをクリックするとインラインDiffが表示される。

Push と Pull

Push（アップロード）

ローカルのcommitをリモート(GitHub)に送信

方法1: ステータスバーの 🔄 ボタン

方法2: Source Control の ... メニュー → Push

方法3: Cmd+Shift+P → Git: Push

Pull（ダウンロード）

リモートの最新変更をローカルに取得

方法1: ステータスバーの 🔄 ボタン

方法2: Source Control の ... メニュー → Pull

方法3: Cmd+Shift+P → Git: Pull

ステータスバー左下に ↑2 ↓1 のように未push/未pullのcommit数が表示される

GitLens: その他の機能

Commit Graph

ブランチの分岐・マージを視覚的に表示。コマンドパレットから「GitLens: Show Commit Graph」。

File History

ファイルの変更履歴を時系列で表示。右クリック → 「Open File History」。

Line History

特定の行がいつ・なぜ変更されたかの全履歴を表示。

Compare

任意の2つのcommitやブランチ間の差分を比較。

Discard Changes（変更を破棄）

ファイルの変更を元に戻す

Source Controlパネルで、変更ファイルの右にある↩（Discard Changes）ボタンをクリック。

= git checkout -- ファイル名

注意: 未commitの変更は完全に失われる。元に戻せない！

全ファイルの変更を破棄

CHANGES の右にある ↩ ボタンで全ファイルの変更を一括破棄。

安全策: Stash（一時退避）を使うとあとで復元可能。

Git Stash（一時退避）

作業中の変更を一時的に保存

ブランチを切り替えたいが、今の変更をcommitしたくない時に使う。

# VS Codeでの操作
Source Control ... → Stash → Stash (include Untracked)

# 復元
Source Control ... → Stash → Pop Latest Stash

ターミナルでの操作

$ git stash
$ git stash pop

よくある失敗と対処法

間違ったブランチにcommitした

mainブランチで直接commitしてしまった。

対処: ターミナルで git reset --soft HEAD~1 → 正しいブランチに切り替え → 再commit

pullせずにpushして拒否された

「rejected - non-fast-forward」エラー。

対処: まずPull（またはPull with Rebase）→ コンフリクト解決 → 再Push

大きなファイルをcommitしてしまった

.venvや node_modules をcommitしてしまった。

対処: .gitignore に追加 → git rm -r --cached .venv/ → 再commit

Step 1: 任意のファイルを編集して保存

Step 2: Cmd+Shift+G でSource Controlを開き、変更ファイルの + をクリック（Stage）

Step 3: メッセージ欄に feat: update file と入力して Cmd+Enter

Step 4: ステータスバーの同期ボタン、または ... → Push でリモートに送信

演習2: ブランチ作成とマージ

1. ステータスバー左下のブランチ名をクリック → 「Create new branch」→ feature/test

2. ファイルを編集 → Stage → Commit

3. ステータスバーでブランチ名をクリック → main に切り替え

4. Source Control ... → Branch → Merge Branch → feature/test を選択

5. マージ完了を確認して Push

演習3: Diff確認とGitLens

1. ファイルを数行変更して保存（commitしない）

2. Source Controlパネルでファイルをクリック → Diffビューを確認

3. エディタ左のガターの色付きバーをクリック → インラインDiff

4. GitLensがインストール済みなら、行末のblame情報を確認

5. Cmd+Shift+P → 「GitLens: Show Commit Graph」でグラフを確認
