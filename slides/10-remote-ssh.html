UIはローカルPC、実行はリモートサーバー。ファイルはサーバー上にあるので、大規模データや高性能GPUをリモートで使える。

なぜ Remote-SSH？

高性能ハードウェア

サーバーのCPU 160スレッド、GPU RTX 4090を活用。ローカルPCの性能に依存しない。

大規模データ

データセットをダウンロードせずにサーバー上で直接処理。ネットワーク転送なし。

同じ操作感

ファイル操作、ターミナル、デバッグ、全てローカルと同じ感覚で使える。

環境の統一

チーム全員が同じサーバー環境で開発。「自分のPCでは動く」問題がなくなる。

Remote-SSH 拡張のインストール

インストール手順

1. Cmd+Shift+X で拡張パネルを開く

2. 「Remote - SSH」を検索

3. Microsoft 製の「Remote - SSH」をインストール

4. 「Remote - SSH: Editing Configuration Files」も自動インストールされる

CLI でインストール

$ code --install-extension ms-vscode-remote.remote-ssh

SSH 鍵の設定

Terminal — SSH Key Setup
# 1. SSH鍵を生成（初回のみ）
$ ssh-keygen -t ed25519 -C "your_email@example.com"
Generating public/private ed25519 key pair.
Enter file: [Enter] (デフォルトでOK)
Enter passphrase: [Enter] (空でもOK)
# 2. 公開鍵をサーバーにコピー
$ ssh-copy-id pws-ubuntu-server@100.104.225.55
Number of key(s) added: 1
# 3. パスワードなしで接続確認
$ ssh pws-ubuntu-server@100.104.225.55
Welcome to Ubuntu 24.04

SSH Config ファイルの設定

~/.ssh/config

Host pws-160core
  HostName 100.104.225.55
  User pws-ubuntu-server
  IdentityFile ~/.ssh/id_ed25519

Host pws-gpu
  HostName 100.126.144.110
  User root
  IdentityFile ~/.ssh/id_ed25519

# LAN内からの接続
Host pws-160core-lan
  HostName 10.0.70.42
  User pws-ubuntu-server

Host名を短くしておくと、VS Codeの接続先リストが見やすくなる

リモートでのファイル編集

ローカルと同じこと

  • ファイルの作成・編集・保存
  • エクスプローラでフォルダ操作
  • 検索・置換 (Cmd+F, Cmd+Shift+F)
  • Git操作 (Source Control)
  • デバッグ (F5)
  • ターミナル (Ctrl+`)

違うこと

  • ファイルはサーバー上にある
  • ターミナルはサーバーで実行
  • 拡張はリモート用が必要
  • ネットワーク切断でセッション切れ
  • ドラッグ＆ドロップは転送になる

拡張機能: ローカル vs リモート

UIに関する拡張 (ローカル)

  • キーバインド
  • Japanese Language Pack

開発に関する拡張 (リモート)

サーバー側で動作

  • Python / Pylance
  • Ruff / Error Lens

  • Jupyter

注意: リモートに初めて接続すると、リモート側にも拡張をインストールする必要がある。「Install in SSH: hostname」ボタンで対応。

接続の注意点

ホームディレクトリを開かない

「Open Folder」で /home/username を開くと、VS Codeが全ファイルをインデックスして重くなる。

対策: 必ずプロジェクトのサブフォルダ（例: /home/username/my_project）を指定する

ファイル削除にゴミ箱はない

リモートでファイルを削除すると、ゴミ箱を経由せず即座に消える。

対策: 重要なファイルは Git で管理。削除前に確認する習慣。

ネットワーク切断

WiFiが切れると接続が切断される。未保存の変更は失われる可能性。

対策: Auto Save を ON にする。"files.autoSave": "afterDelay"

ポートフォワーディング

リモートのWebアプリにローカルからアクセス

リモートサーバーで python -m http.server 8000 を起動

→ VS Code が自動でポートフォワードを検出

→ ローカルの http://localhost:8000 でアクセス可能

手動でフォワーディング

Cmd+Shift+P → Forward a Port

または PORTS パネルで + ボタン

例: Jupyter Notebook (8888)、Flask (5000)、FastAPI (8000)

ファイル転送

ローカル → リモート

エクスプローラにドラッグ＆ドロップでアップロード。

または: scp local.txt pws-gpu:~/

リモート → ローカル

ファイルを右クリック → 「Download」。

または: scp pws-gpu:~/result.csv .

大きなファイルの注意

数GB以上のファイルはドラッグ＆ドロップではなく、scp / rsync を使うこと。

Reconnect と tmux

接続が切れたとき

VS Codeは自動的に再接続を試みる。失敗時は Cmd+Shift+P → Remote-SSH: Connect to Host で再接続。

tmux で長時間ジョブを保護

$ tmux new -s training
$ python train.py # Ctrl+B, D でデタッチ
$ tmux attach -t training # 再接続

SSH切断後もtmux内のプロセスは継続。ML学習に必須。

セキュリティの注意

SSH秘密鍵は絶対に共有しない

秘密鍵（id_ed25519）は自分だけのもの。公開鍵（.pub）は共有OK。

パスフレーズ推奨

ssh-keygen でパスフレーズを設定。macOS Keychain で自動入力。

不要なポートフォワードを閉じる

使い終わったポートはPORTSパネルで削除する。

Tips: 接続を快適にする

SSH Keep Alive

~/.ssh/config に追加:
ServerAliveInterval 60
接続切断を防ぐ。

Auto Save

リモート設定に追加:
"files.autoSave": "afterDelay"
切断時のデータロス防止。

デフォルトフォルダ

SSH Config に追加:
RemoteForwardAgent yes
Git の鍵転送。

多段SSH

踏み台サーバー経由:
ProxyJump bastion
ファイアウォール越え。

まとめ

ローカルUI + SSH + リモート実行。VS Code Serverがサーバーで動く。

リモート開発

ファイル編集・ターミナル・デバッグ、全てローカルと同じ操作感。

注意点

ホームディレクトリを開かない、Auto Save ON、Git で管理。
